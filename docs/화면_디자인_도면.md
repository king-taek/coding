# 화면 디자인 '도면(Datum)' — 토큰·구조·모션

앱의 UI 디자인은 **'도면' 하나**다(2026-07 확정). 이전에 검토했던 다른 *스타일*과 그
스위처는 제거했다.

단, 두 가지는 **축이 다르므로** 공존한다:
- **색 모드 3종** — 같은 디자인의 세 가지 시트. `theme.PALETTES` + `set_color_mode()`.
  | 키 | 이름 | 컨셉 | bg | 채도지표 |
  |---|---|---|---|---|
  | `light` | 벨럼 | 따뜻한 제도지 + 청사진 잉크 | `#ECE9E2` | 0.010 |
  | `dark` | 청사진 | 짙은 청색 감광지 + 백선 | `#12304C` | 0.228 |
  | `graphite` | 흑연 | 불 끈 제도지 + 흑연 선 | `#1C1A15` | 0.028 |
  두 어두운 모드는 색 온도·채도가 **반대**다(청사진 = 유채·차가움 / 흑연 = 무채·따뜻함)
  — 서로의 변주가 아니라 다른 판단이어야 한다(`test_color_mode` 가 고정).
  ★ 청사진의 키는 `"dark"` 로 유지한다 — 기존 prefs 가 마이그레이션 없이 동작한다.
  ★ 모드 목록을 테스트·캡처 하네스에 **복제하지 마라**. `color_mode_keys()` 를 읽으면
    새 모드를 추가하는 순간 모든 대비·포커스·타깃 계약이 자동으로 걸린다.
- **셋업 배치안 A/B/C** — *비교용 임시* 발판(`pages/setup_layouts.py` + 상단 스위처).
  배치안이 확정되면 미선택 안과 스위처를 함께 제거한다.

## 컨셉

따뜻한 **벨럼 제도 시트** 위의 **청사진 잉크**. 검토 화면이 '카드 목록' 이 아니라
**치수가 적힌 제도 시트**로 읽히게 한다.

- 고정 컬럼 헤더(타이틀블록): `슬롯 · 기준·검증·후보 · 거리(µm) · 판정`
- 면 없는 **하이라인 눈금** 행(간격 0) + 우측 **거리 컬럼 눈금**(`role="vrule"`)
- 판정은 **스탬프 칩** — 예외(허용 초과/매치 없음)만 노출
- 얇은 표제(weight 300 / 자간 −1), **수치는 모노**
- 모서리는 중간 라운드(`radius 9` / `radius_sm 6` / `chip_radius 8`) — '너무 각지다'는
  지적에 따라 2·1·0 에서 올렸다.  계측기의 정밀함은 얇은 표제·하이라인 눈금·모노
  수치가 담당한다(형태가 아니라 조판이 컨셉을 진다).
  ※ 이 문서가 옛 값(radius 2 / 칩 0)을 서술하는 동안 코드는 9/8 이었다 — 단일 출처가
    스스로를 배신하면 다음 사람이 문서를 믿고 되돌린다.  값을 바꾸면 여기도 고쳐라.
- 무광 — 글로우·그림자 없음. 강조는 청사진 블루 `#2C5A86` 하나뿐

## 아키텍처 (단일 출처)

- **`ui/theme.py`**
  - `COLORS`: 18색(bg/panel/elev/line/**line_strong**/line2/ink/ink2/mute/accent…/pass/
    danger/warn/focus/**thumb_frame**). 모듈 전역(`theme.INK` 등)은 인라인 f-string 용.
  - **경계선 3등급을 구분해서 쓴다** — 이게 WCAG 1.4.11 의 전부다:
    | 토큰 | 용도 | 하한 |
    |---|---|---|
    | `line_strong` | **상호작용 컨트롤의 평상시 경계**(입력란·버튼·타일·체크박스·스위치 트랙·스크롤바) | 3:1 (elev/panel/bg 전부) |
    | `line` | 구조(카드 외곽·행 구분 눈금·**비활성 파선**) | 3:1 (panel/bg) |
    | `line2` | 장식 전용(툴팁·키캡·hover 변화·'없음' 칩) | 없음 |
    `line2` 를 상호작용 평상시 경계에 쓰면 `test_a11y_controls` 가 실패한다.
  - `PROFILE`(:class:`Profile`, frozen): 구조 파라미터 — 서체 크기·굵기·자간, radius 계열,
    밀도(margin/pad/row_gap), control_h, 칩/토글 크기, thumb_default_px, focus_ring_px,
    motion_scale. 화면이 **생성 시점에** 읽는다.
  - `TOKENS` = `_derive_tokens()`: 색 + 틴트 + 서체 + 구조(px)·칩·행·눈금 토큰.
  - `render_qss(text)` → `$token` 치환(미정의 토큰은 KeyError 로 즉시 실패).
    `apply_to_app(app)` → 렌더 후 앱 적용.
- **`ui/style.qss`** — 단일 `$token` 템플릿(빌드 spec 이 이 파일 하나만 datas 에 넣는다).

## 모션 (`ui/motion.py`)

이징 기본 **OutQuart**(빠르게 시작→끝에서 감속). `PROFILE.motion_scale=0.8` 로 제도 시트답게
담백하게 스케일.

- `enabled()` — offscreen(테스트·캡처)·앱 '모션 줄이기'·**OS 동작 줄이기**(Windows SPI) 면
  False → 모든 헬퍼가 즉시 스냅(결정론).
- 화면 전환 `transition_in` — 들어오는 화면이 흐름 방향(앞/뒤)으로 슬라이드+페이드 진입.
  방향은 `main_window._page_order`(셋업→선별→매칭→검토→결과)로 결정.
- 로딩 오버레이 — **불투명도와 위치를 분리한다**(둘을 하나의 t 로 몰면 사용자가 요청한
  두 속도가 사라진다): 불투명도 `FADE_IN_MS 180` **Linear**(스크림 디밍이 슬램하지 않게),
  위치 `RISE_IN_MS 300` **OutQuad**(끝에서 감속하며 중앙에 안착 — OutQuart 는 페이드가 끝나는 시점에 잔여 이동이 0.8px 뿐이라 '두 속도'가 사라졌다).  퇴장 `FADE_OUT_MS 140`.
  \+ **최소 표시 350ms 래치** — 이 래치는 모션이 아니라 **타이밍 위생**이므로
  `motion.enabled()` **밖**에 둔다(안에 두면 '모션 줄이기' 사용자만 깜빡임을 받는다).
- 로딩바 — 결정형은 tick 마다 **Linear**(tick 마다 OutQuart 면 매 갱신이 감속해 절뚝인다) /
  busy 등속 **혜성 스윕**(진행 방향 앞쪽이 머리 — 알파는 증가 순서, 꼬리 하한 0.45) /
  숨쉬는 arc 스피너.  스피너 링·혜성 트랙은 `LINE2` 다(`LINE` 은 지시자와 1.84~1.90:1).
  **CLAUDE.md 로딩 계약**(`set_progress(done,total,msg)` 의미·증가 tween·감소 스냅) 유지.
- 미세 피드백 — 버튼 프레스 opacity 딥(0.92), 행 상태 전환 펄스, 프로그램적 스크롤만 애니메이트
  (휠은 네이티브).
- 셋업 상단 보기 옵션 — **색 모드 3택 칩** + **'모션 줄이기' `SwitchRow`**
  (prefs `color_mode` / `reduce_motion` 으로 영속).  두 컨트롤의 **어휘를 통일**한다:
  이전엔 나란한 두 설정이 스위치와 체크박스로 서로 달랐고 하필 약한 쪽이 모션이었다.
- **파괴적 액션에 방향키 즉시 커밋을 두지 마라.** 색 모드·배치 전환은 페이지 재생성이라,
  `OptionGroup(activate_on_arrow=False)` 로 방향키는 포커스만 옮기고 Space/Enter 로
  확정한다(그러지 않으면 키보드로 훑기만 해도 화면이 날아가고 포커스를 잃는다).
- **`CollapsibleSection` 도 `motion` 게이트를 지킨다** — 앱 유일하게 무시하던 위젯이었다.
  애니메이션이 끝나면 `maximumHeight` 를 **풀어야** 한다: 안 풀면 펼친 시점의 sizeHint 에
  높이가 고정돼 나중에 커지는 내용이 조용히 잘린다('?' 도움말이 눌러도 반응 없어 보였다).

## 셋업 화면 컨트롤 규칙 (2026-07 개편)

- **모드 on/off 는 명시적 컨트롤에서만 유도한다.** 접이식 섹션의 펼침 상태를 기능 스위치로
  쓰지 마라 — 예전에 `_legacy_section.is_expanded()` 가 엔진 모드였고, 설명을 읽으려고
  펼치기만 해도 좌표 매칭이 유사도 엔진으로 바뀌었다. 지금은 엔진 카드에 접이식이 아예
  없다(`_current_engine_mode()` 는 `legacy_switch` + `legacy_group` 만 읽는다).
- **무효해진 파라미터는 숨기지 말고 비활성**한다. 스크롤 안 show/hide 는 내용이 튀고,
  비활성은 '허용 오차는 좌표에, 임계치는 구형에 속한다'를 눈으로 가르쳐 준다.
  단, 비활성 **모습이 실제로 달라야** 한다 — 속성 선택자(`[role="primary"]`)가 일반
  `:disabled` 보다 특이도가 높아 전용 규칙이 없으면 꽉 찬 채로 남는다.
- **상태는 컨트롤 안에 둔다.** 옆 라벨에 상태를 두지 마라(진행 범위는 타일 자기 라벨이
  `일부 슬롯 (12/40)` 로 바뀐다).
- **배타 선택은 `OptionGroup`**(타일 전체가 클릭영역). 선택 틴트는 **QSS `:checked` 만**
  칠한다 — 위젯에 인라인 스타일시트를 쓰면 라이트/다크 대응이 깨지고, 실제로 죽은 네온
  팔레트가 하드코딩된 사례가 4곳 있었다.
- 시작 버튼은 유효할 때만 활성. 이유는 툴팁이 아니라 **인라인 오류 + 버튼 옆 문구**로.
  기존 `QMessageBox` 검증 경로는 보존한다(늦게 드러나는 실패를 계속 잡는다).
- **로딩 오버레이**: 스크림은 반투명(뒤 화면이 보인다 — 뒤 본문 대비도 게이트 5.0 을
  지킨다), 내용은 불투명 패널에.  패널은 중앙 `RISE_IN_PX 32` 아래 · opacity 0 에서
  중앙 · 1 로 안착, 퇴장은 12px·더 짧게.  진행바는 `BAR_STAGGER_MS 210` 늦게 8px 밀려
  들어온다.  ★ 비교 대상은 페이드가 아니라 **위치 안착**(`RISE_IN_MS`)이다 —
  60ms·110ms 둘 다 패널보다 먼저 도착했다(110 은 88+128=216 vs 안착 240).  패널 폭은 `PANEL_W 424`
  **고정** — sizeHint 를 쓰면 메시지 길이·busy↔결정형 전환마다 폭이 뛴다.
  ★ 패널에 그래픽 이펙트가 걸려 있는 동안 **이펙트를 중첩하지 마라**(QPainter 충돌
  경고) — 여백을 맞바꿔 슬라이드한다.  그리고 등장이 끝나면 이펙트를 **떼라**:
  걸린 동안 스피너 1프레임마다 패널 전체가 오프스크린으로 다시 렌더된다.
- **오류 줄은 자리를 예약한다** — show/hide 하면 카드 높이 30px·옆 카드 정렬 23px 가
  흔들린다.  문자열만 비운다.

## 접근성 계약 (2026-07 — 실측으로만 판정한다)

세 항목 모두 **정적 캡처로는 통과처럼 보였고** 실측에서 실패했다. 그래서 규칙과 함께
"어떻게 속았는지"를 남긴다. 회귀 테스트는 `dev/tests/test_a11y_controls.py`.

- **비-텍스트 대비(1.4.11)는 계산으로 판정한다.** '절제된 얇은 경계'처럼 보였던 것이
  실제로는 라이트 1.91 / 다크 1.50 — **보이지 않는 컨트롤**이었다. 위 3등급 표를 지켜라.
  플레이스홀더는 Qt 기본(본문 50% 알파, 3.31)을 쓰지 말고 `placeholder-text-color: $mute`.
- **포커스 링은 '선언'이 아니라 '렌더된 픽셀'로 판정한다.** 두 가지로 실패했다:
  - **링이 아예 없음** — `QPushButton[role="ghost"]` 의 `border-color` 가 일반
    `QPushButton:focus` 와 **특이도 동급·후순위**라 링 색을 덮어썼다. 역할별
    `:focus` 규칙을 **반드시 따로** 선언하라(`primary`·`ghost`·`danger`·`warn`).
  - **링이 있는데 안 보임** — 채운 컨트롤의 링은 페이지 배경이 아니라 **자기 채움**과
    대비해야 한다. `focus` vs `accent` 는 1.23:1 이다. 채운 primary 는 `on_accent`(6.5/8.57).
  - **슬라이더는 QSS 로 불가능** — Qt 는 서브컨트롤에 `:focus` 를 지원하지 않고
    (`QSlider::handle:horizontal:focus` 무시), 위젯 `border` 도 서브컨트롤이 스타일링된
    슬라이더에선 렌더되지 않는다. `NoWheelSlider.paintEvent` 가 직접 그린다 — 지우지 마라.
- **클릭 타깃은 2층이다.** 액션 등급(타일·액션바 버튼) = `control_h_lg` **44**(2.5.5 AAA),
  밀집 등급(체크박스 행·`?`·슬라이더) = `target_min` **26**(2.5.8 AA 24 초과).
  *모든* 컨트롤에 44 를 강제하지 않는 이유는 800×600 지원이 하드 요구사항이기 때문이다
  (세로 스크롤 폭증). 행 전체가 클릭영역인 컨트롤은 **행 높이**가 실제 타깃이다.
- **채움 위에 글자를 얹지 마라.** 진행바 안의 숫자는 채움이 지나가면 2.41/1.85 로
  붕괴했다. 수치는 바 **밖** 모노 라벨(`role="progressCount"`).
- **비활성은 패턴(파선)으로 말한다.** 옅은 실선은 평상시와 구분되지 않는다. 비활성
  primary 는 면을 비워라(면을 `line2` 로 채우면 라벨이 3.42 로 떨어진다).
- **Qt 스핀 버튼을 사용자 화면에 쓰지 마라.** QSS 로는 삼각형 화살표를 그릴 수 없어
  (이미지 리소스 필요) 납작한 막대로 잘리고 폭도 ~10px 이다. `NoButtons` + 진짜
  `QPushButton` −/+ 를 쓴다(`setup_page._stepper_button`).
- **맨 `QWidget` 컨테이너는 전역 `QWidget { background: $bg }` 를 물려받는다** — 패널
  면 위에 색이 다른 띠로 보인다. 역할을 주고 `background: transparent` 로 못 박아라.

## 불변식 (깨지 말 것)

- 전 기능 색상쌍 **WCAG AA 여유(≥5.0, 포커스·플레이스홀더 ≥4.5)** — **3개 색 모드 전부**
  (`dev/tests/test_variants.py`, `test_color_mode.py`, `test_a11y_controls.py`).
  ★ **합성면까지 재라**: "전 쌍 통과"라는 주장이 한 번 거짓이었다 — 표가 컨트롤 경계만
  재고, 실제 하한이던 반투명 틴트 위 라벨(4.66)·스크림 아래 본문(4.43)·로딩 지시자
  (1.84)를 빼놨다.  알파는 표·테스트에 **복제하지 말고** `theme.ACCENT_TINT` 등에서
  읽어라(복제하면 토큰을 바꿔도 옛 값을 계속 재서 통과한다).
  ★ **경고 채널은 본문과 구분되어야 한다** — 라이트 `warn` 이 `ink` 와 바이트 단위로
  같았는데, 대비표는 그 쌍을 15.68 로 적어 **표에서 가장 좋은 점수**로 보이게 했다.
  어두운 모드에서는 warn·ink 가 둘 다 밝아 휘도비로 구분할 수 없으니 **채널 차이**로 재라.
- **주요 액션은 스크롤 밖에 고정**(`_pinned_action_bar()` 기본 True). 800×600 에서
  [검증 시작]이 화면 밖으로 밀려났던 결함 — 배치안의 차이로 두지 않는다.
- **800×600 대응, 가로 스크롤 0** — 행이 뷰포트 폭 기준으로 재클램프
  (`_row_width` 가 조상 QScrollArea 의 viewport 폭을 쓴다) — `test_match_review_clamp.py`.
- `PROFILE` 리터럴은 클램프 계산의 전제 → 바꾸면 `test_variants.py` 의 기준선 핀과
  `_reserved_fixed_px` 를 함께 확인한다.
- **QScrollArea 뷰포트 배경은 '맨 선언' 스타일시트로 주지 않는다** — 자식으로 캐스케이드돼
  버튼의 `:checked` 배경을 덮어쓴다. objectName 으로 스코프할 것
  (`QScrollArea > QWidget#qt_scrollarea_viewport`).
- 디자인 **스타일**은 하나 — 옛 5-스타일 스위처 기계(`VARIANTS`/`set_variant`/
  `_rebuild_pages`/`variant_selected` 등)를 되살리지 않는다(`test_variants.py` 가 이름을
  부분문자열로 검사). 색 모드와 배치안은 축이 달라 별도 이름을 쓴다
  (`PALETTES`/`set_color_mode`, `LAYOUTS`/`_recreate_pages`).
- **prefs 마이그레이션 주의**: `patch()` 는 전체 dataclass 를 저장하므로, 어떤 필드든 한 번
  patch 되면 **모든 기본값이 파일에 박힌다**. 따라서 기본값을 바꾸는 것만으로는 기존
  사용자를 옮길 수 없다 — 새 키(예: `legacy_enabled: bool | None`)를 도입해 '미설정'을
  표현하고 순수 함수로 1회 유도하라(`prefs.resolve_legacy_state`).
- **셋업 화면 개발자 모드 계약**: `dev_bench_btn`/`dev_label_btn` 속성명, `_toggle_dev_mode()`,
  `_refresh_dev_buttons()` 의 액션바 인덱스 가정([0]=update, [1..2]=dev)을 유지한다.
  액션바에 새 위젯은 `addStretch()` **뒤**에 붙일 것(`test_setup_controls.py` 가 고정).
- 동작/리소스(로딩바·모션·행 규칙·헤더·모드 스위치)를 바꾸면 대응 테스트를 추가/갱신한다.

## 미결 (알고 있으나 이번에 손대지 않음)

재채점에서 세 심사관이 **독립적으로 같은 결론**에 도달한 항목들이다.  분석을 버리지 않기
위해 남긴다 — 다음 세션이 처음부터 다시 도출하면 낭비다.  각 항목에 **왜 지금 안 했는지**를
함께 적었다.

1. **레이아웃 층이 템플릿에 가깝다.**  radius 9 · 1px 보더 · pad 20 · 간격 28 의 동일 카드가
   반복되고, 자동화 수준/진행 범위 카드는 픽셀 단위로 같아 라벨을 지우면 구별되지 않는다.
   이진 선택 두 개를 694×58 타일로 부풀린 것도 같은 문제다.
   처방(심사관): 두 이진 선택은 카드 격을 버리고 폭 320 세그먼트로 강등, 화면을 3덩어리로 재편.
   **왜 지금 안 했나** — 정보 구조 재편이라 **배치안이 확정된 뒤**가 맞다.  어느 안(A/B/C)을
   남기냐에 따라 재편 대상과 순서가 달라진다.
2. **면이 위계를 못 만든다.**  실측 panel/bg **1.093** · elev/panel **1.063** — 카드와 입력란이
   같은 무게로 읽힌다.  처방: bg 를 한 단 낮춰 panel/bg ≥1.19.
   **왜 지금 안 했나** — 라이트 바탕(`#ECE9E2`)은 사용자가 고른 '벨럼' 컨셉의 근간이라
   임의로 바꾸지 않았다.  바꾸려면 사용자 확인이 필요하다.
3. **'도면' 컨셉이 셋업 화면에는 얇다.**  눈금·타이틀블록·치수가 0개고, 폴드 위 모노는
   수치 모노화로 일부만 생겼다.  컨셉은 검토 화면(A2)에 살아 있고 셋업은 카드 스택이다.
   **왜 지금 안 했나** — 1번과 같은 작업이다(카드 스택을 시트로 바꾸는 일).
4. **안티-AI-슬롭 판정 '실패'.**  팔레트 3종·상태색이 실제로 바뀌는 판정 배지·파선 비활성
   어휘·Qt 스핀을 실버튼으로 대체한 결정에는 사람의 판단이 있으나, **레이아웃 층**이
   auto-layout 결과물로 읽힌다는 판정이다.  1·3 을 하면 함께 올라간다.
5. **배치안 3종 + 상단 스위처는 의도적으로 유지한다.**  사용자가 "3개의 안을 그대로 두고
   나중에 처리" 로 결정했다.  정리 커밋(미선택 2안 + `pages/setup_layouts.py` + 스위처 +
   `dev/tests/test_setup_layouts.py` 제거)은 확정 뒤에 한다.
   그때까지 **미선택 2안은 데드 코드이고 유지비가 든다** — 공유 레이어를 고칠 때마다 세 안
   전부에서 확인해야 한다(실제로 B안이 `_build_device_row()` 를 쓰지 않아 공유 수정이
   하나도 적용되지 않은 사고가 있었다).

### 이번 라운드에서 배운 것 — 측정이 거짓을 보증할 수 있다

세 번 같은 패턴에 걸렸으므로 규칙으로 남긴다:

- **하네스가 모드·항목 목록을 복제하면, 새로 추가된 것은 측정되지 않은 채 '전 쌍 통과'로
  보고된다.**  색 모드를 3개로 늘린 뒤에도 대비표에 흑연 열이 없었다.
  → 목록은 항상 `theme.color_mode_keys()` 처럼 **단일 출처에서 읽는다.**
- **표에 없는 쌍이 진짜 하한이다.**  "컨트롤 경계 32쌍 통과"는 사실이었지만, 실제 하한은
  표에 없던 합성면(반투명 틴트 위 라벨 4.66 · 스크림 아래 본문 4.43 · 로딩 지시자 1.84)이었다.
  → 새 면·새 틴트를 만들면 **그 쌍을 표에 넣는 것까지가 작업이다.**
- **테스트에 상수를 복제하면 토큰을 바꿔도 통과한다.**  링 색·틴트 알파는 렌더된 QSS·
  `theme.ACCENT_TINT` 에서 **읽어서** 검사한다.
- **캡처 하네스가 서로를 지울 수 있다.**  `capture_setup.py` 가 디렉터리를 비우므로 순서를
  바꾸면 포커스 캡처가 조용히 사라진다 — 실제로 "21장"이라고 보고한 시점에 0장이었다.
  → 증거 생성은 `capture_all.py` 한 진입점에서만 하고, 빠지면 `assert` 로 실패시킨다.
- **통과하지 않는 규칙을 테스트로 박지 않는다.**  '경고는 강조보다 채도가 낮아야 한다'를
  넣으려다 뺐다 — 이 프로젝트는 상태색(PASS/DANGER/WARN)이 눈을 끄는 것을 **의도**하고,
  실제로 라이트 warn·danger 는 accent 보다 채도가 높다.  거짓 불변식은 다음 사람을
  잘못된 방향으로 몬다.
