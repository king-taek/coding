2. 좌표 계산이 하는 일

2-1. 왜 필요한가

장비가 남기는 파일에는 결함의 절대 좌표만 있습니다. 사람이 보는 col 5 / row 4 같은 die 번호와 die 내부 위치는 앱이 계산해야 합니다. 이 계산은 두 곳에 쓰입니다.

용도필요한 것틀리면 생기는 일
매칭기준·검증 양쪽이 같은 규칙이면 됨 (절대값은 달라도 무방) 같은 결함을 못 찾음 → 검증 누락
화면·엑셀 표기장비 화면과 같은 절대값이어야 함 사람이 장비와 대조할 때 혼선

이 구분이 중요한 이유

지금까지 발견된 오류는 대부분 표기만 틀리고 매칭은 정상이었습니다. 양쪽이 똑같이 틀리면 상쇄되기 때문입니다. 그래서 매칭이 잘 된다는 사실이 좌표가 맞다는 증거가 되지 않습니다. 실제로 RDL4 의 row 오류는 몇 달간 매칭을 통과하며 숨어 있었습니다.

2-2. 입력과 출력

[입력] 스캔 결과 폴더 ├ ColorImageGrabingInfo.ini 결함의 절대 X/Y (Camtek) ├ Params_WaferInfo.ini die 간격 · 웨이퍼 직경 · 웨이퍼 중심 ├ Wafer2Table.ini 웨이퍼 정렬 변환 (중심의 2순위 소스) └ *.001 XREL/YREL · XINDEX/YINDEX · DiePitch (KLA) │ ▼ [출력] DefectCoord(col, row, x, y) col, row : 웨이퍼 맵의 die 번호 (장비 화면과 같아야 함) x, y : die 내부 위치 (µm) (매칭 거리 계산에 사용)

3. 현재 계산 방식

3-1. 핵심 개념 — die 격자와 웨이퍼

die 격자는 장비 좌표계에 고정된 바둑판입니다. 그 위에 둥근 웨이퍼를 올려놓습니다. 웨이퍼가 온전히 덮는 칸들이 실제 die 이고, 번호는 그 첫 칸/마지막 칸부터 셉니다.

격자 칸 번호(y_index) 0 1 2 3 4 5 6 7 8 ────────────────────────────────────────────────── RDL4 가 덮는 칸 ■ ■ ■ ■ ■ ■ 맨 아래 = 6 UDS-PIDS3 가 덮는 칸 ■ ■ ■ ■ ■ ■ 맨 아래 = 7 → die 크기가 같아도(둘 다 44905 µm) 웨이퍼가 놓인 위치가 다르면 번호 기준이 다르다

3-2. 변환식

Camtek INI
  x_index = floor(X / pitch_x)              y_index = floor(Y / pitch_y)
  col     = x_index − col_origin            row     = row_total − y_index
  x       = floor(X − x_index × pitch_x)    y       = floor(Y − y_index × pitch_y)

     col_origin = ceil((Center_X − 직경/2) / pitch_x)      웨이퍼에 온전히 들어오는 첫 열
     row_total  = floor((Center_Y + 직경/2) / pitch_y) − 1  온전히 들어오는 마지막 행

KLA .001
  col = XINDEX + zero_x                     row = YINDEX + zero_y
  x   = round(XREL)                         y   = round(DiePitchY − YREL)

     zero_x = −ceil((SampleCenterLocation_X − 직경/2) / DiePitchX)
     zero_y = −ceil((SampleCenterLocation_Y − 직경/2) / DiePitchY)

Camtek 파일명 — 보정 없이 토큰 그대로 사용 (장비가 이미 계산한 값)

세 소스가 같은 규칙을 쓴다

Camtek 은 Y 가 아래로 커져서 마지막 완전 행이 row 0 이고, KLA 는 Y 가 위로 커져서 첫 완전 행이 row 0 입니다. 축 방향만 반대이고 '온전히 들어오는 die 부터 0번' 이라는 규칙은 같습니다. 그래서 두 장비가 자동으로 정렬됩니다.

3-3. 값을 정하는 우선순위 사슬

die 간격(pitch) 웨이퍼 중심 ───────────────────── ───────────────────── 1 Params_WaferInfo.ini 1 Params_WaferInfo.ini DieStep_X / DieStep_Y [Geometric] Center_X / Center_Y 2 ProductInfo.ini (0.000000 은 '미기록' 으로 취급) XDieIndex / YDieIndex 2 Wafer2Table.ini 3 ProductInfo.ini 정렬 변환을 풀어서 중심 산출 CustomerDiePitch_X / _Y 3 (없음) 4 models.py 상수 → col_origin = 상수 2 ↑ 모든 후보가 자체검산을 통과해야 채택 → row_total = ceil(직경/pitch_y) 자체검산: 모든 결함에서 INI Col == floor(X / pitch_x) (X 축은 등호, 완화 금지) Y 축은 레시피별로 차이가 상수이기만 하면 통과

3-4. 안전장치

장치동작막는 사고
pitch 자체검산읽은 pitch 로 Col==floor(X/pitch) 가 전 항목에서 성립해야 채택 다른 자재의 pitch 를 잘못 채택 → x = −1,652,266 µm
die 크기 후보 제외DieSize 계열은 후보에서 아예 뺌 (크기 ≠ 간격) 스크라이브 있는 자재에서 die 폭의 23% 누적 오차
상식 범위 검사원점이 0..200 밖이면 폴백 + 경고특이행렬·손상된 파일
절대좌표 폴백pitch 를 못 정하면 die 로 안 쪼개고 절대좌표로 매칭 기하를 모른다고 매칭까지 막히는 것
프레임 통일한 실행에 die-내부와 절대좌표가 섞이면 전부 절대좌표로 통일 슬롯 전체가 '매치 실패' 로 보이는 것
조용한 폴백 금지모든 폴백·거부 경로가 경고 로그를 남김틀린 채로 아무도 모르는 상태

기능동작잡는 리스크
a경계 여유 경고 웨이퍼 끝이 die 경계에서 5 % 이내면 "이 자재는 원점이 흔들릴 수 있음" 안내 R-2 — 경계 자재

(c) 의 실증 — 현재 dev/좌표 확인 폴더가 이 신호에 걸립니다 (row 가 1..6 으로 0 에 안 닿음). 그 폴더는 실제로 원점이 1 큰 상태이므로 신호가 옳게 작동합니다. 다만 결함이 적은 웨이퍼에서는 헛경고가 나므로 충분히 퍼진 경우에만 떠야 합니다.

8-3. 매칭 개선 — layer 간 계통 이동 보정

참고 저장소(king-taek/Defect_Tracking)의 matcher.py 에 이 저장소에 없는 유용한 기능이 있습니다. PI ↔ RDL 처럼 다른 layer 사이에서 같은 결함을 잘 찾는 이유가 이것입니다.

1. ±1 die 안에 후보가 정확히 1개인 쌍만 모은다        (모호한 건 제외)
2. 그 쌍들의 dx, dy 의 중앙값 = 두 스캔의 계통 이동량
3. 매칭은 그 이동량을 뺀 잔차로 판정                    (거리 보고는 보정 전 실제 거리)

   안전장치:  표본 ≥ 3쌍  ·  MAD ≤ 허용오차(일관성)  ·  |이동량| ≤ 상한
              상한을 넘으면 정합오차가 아니라 die 라벨링 불일치 → 보정하지 않음
항목참고 저장소이 저장소에 넣을 때
도입 가치좌표가 상수 기반이라 필수 좌표는 이미 정확 → 물리적 정렬 차이 대응용
이동량 상한1000 µm더 낮게 (허용오차 수준). 이 저장소에서 큰 이동량은 보정 대상이 아니라 경고 신호
부수 효과—지금 ±1 게이트가 조용히 흡수하던 어긋남이 측정값으로 드러남

참고 저장소와의 좌표식 비교 — 방향은 반대

좌표 계산 자체는 참고 저장소가 이 저장소의 과거 방식입니다: 제품 프로파일 상수(pitch·col_offset=2·row_base=7)를 쓰고, die 인덱스를 INI Col/Row 필드에서 가져옵니다. 이 저장소는 그 네 가지를 전부 실측으로 반증하고 파일 유도로 바꿨습니다 (row_base=7 은 T254 정답 10 과 3 차이).

단, KLA zeroY 는 참고 저장소가 맞았습니다 — SampleTestPlan 최소값에서 뽑는 방식이 실측 5웨이퍼에서 이 저장소의 기하 유도와 같은 답을 냅니다. 이 저장소는 오늘까지 상수 4 를 쓰고 있었습니다.
