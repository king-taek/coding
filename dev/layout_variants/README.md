# 설정 화면 가로 여백 개선 — 후보안 5개

'실행 옵션'·'매칭 설정' 두 카드가 **가로 여백이 너무 많다**는 지적에 대한 후보안이다.
서로 다른 5가지 접근을 각각 구현하고, 성격이 다른 채점자 3명이 13개 기준으로 채점했다.
**어느 안도 미리 적용해 두지 않았다** — 직접 써 보고 고르면 된다.

## 써 보는 법 — **앱 안에서 바로 전환**

다섯 안은 이제 코드에 함께 들어가 있다.  앱을 띄우고 첫 화면(설정) 위쪽
**'배치안'** 줄에서 `원본 · A · B · C · D · E` 를 누르면 그 자리에서 본문이 다시
그려진다(입력해 둔 폴더 경로는 유지된다).  patch 를 적용하고 앱을 재시작할 필요가
없다.

```bash
python main.py        # 띄운 뒤 첫 화면의 '배치안' 버튼으로 비교
```

구현은 `ui/pages/setup_page.py` 의 `_layout_*` 메서드 여섯 개이고 서로 독립이다.
**채택할 안을 정하면** 그 `_layout_*` 하나만 남기고 나머지 구현·`LAYOUT_VARIANTS`
표·'배치안' 버튼(`_build_variant_bar`)·이 폴더·`scripts/try_layout.py` 를 지우면 된다.

아래 patch 들은 각 안을 처음 구현했을 때의 diff 로, 실측·채점 근거를 남기기 위해
보존한다(적용해서 쓰는 용도는 아니다).

## 안별 요약

### B — 카드 내부를 반응형 2열로  (평균 8.28, 1위)
카드 안의 설정들을 `reflow_into_grid` 로 2열로 흘린다. 조건부 위젯(구형 하위선택·임계치)은
**아랫 벌 그리드로 분리**해 토글이 밀리지 않게 했다.

- 1512px **75.1% → 27.8%**, 1280px 70.5% → 23.8%, 800px 52.9% → 8.1%
- **세로가 오히려 짧아진 유일한 안**: 두 카드 319→239px, 페이지 910→862
- 640~2600px 99개 폭에서 토글 y 이동 0건, 가로 넘침 0건
- 알려진 결함: 2560px 에서 두 설정 사이가 906px 로 벌어짐(열 상한이 구조적으로 2).
  구형 ON 시 하위선택 타일이 회색 처리된 '허용 오차' 밑에 앉아 그것의 옵션처럼 읽힘.
  x=379~761 에 382px 짜리 새 구멍. 800px·구형 ON 에서 같은 카드 안이 2열/1열로 갈림.

### E — 본론 열 + 오른쪽 264px 보조 레일  (7.85)
페이지를 2단으로 나눠 설정을 오른쪽 레일로 옮긴다. **구형 토글이 자기 라벨에서 1350px
떨어져 있던 고아 컨트롤 문제를 실제로 해결**한다.

- 알려진 결함: '일부 슬롯' 선택 시 진행 범위 타일이 **12px 겹치고 카드 밖으로 16px 이탈**
  (`set_option_label` 직후 stale `minimumSizeHint()` 를 읽는 순서 문제).
  렌더 이미지 최대 빈 사각형이 44.5% → **51.2%** 로 오히려 커짐(여백이 이동만 함).
  1278px 에서 경로 입력란이 703→240px 로 급락. 구형 ON 시 토글 x 가 14px 이동.

### A — 두 카드를 가로로 나란히  (7.82)
두 카드를 한 그리드 행에 놓고 좁아지면 세로로 접는다.

- 1512px 75.9% → 50.8%, 세로 1044→898(−146)
- 알려진 결함: **876~984px 구간**(1920 모니터 반쪽 = 960px)에서 위 장비 행은 1열,
  아래 옵션 행은 2열이 되어 정렬이 무너짐. 800px 에서는 이득 0.
  `one_row_min_w()` 와 엔진 카드 `addStretch(1)` 약 20줄은 **되돌려도 결과가 동일**
  (죽은 코드, 그 주석이 주장하는 현상은 재현 불가).

### C — 본문 전체를 576px 단일 컬럼으로  (7.18)
페이지 전체에 읽기 컬럼을 씌우고 가운데 정렬. **넓을수록 나빠지는 문제를 유일하게
완전히 해결**(5개 폭 전부 39.8% 고정, 이 항목만 9.0).

- 알려진 결함: **개발자 모드에서 [검증 시작] 버튼 35% 절단**(하한 914 > 상한 640).
  일반 모드 여유도 8px 뿐이라 i18n 문구가 조금만 길어져도 재발.
  폴더 행이 전 구간 1열로 고정되어 본문 1044→1276px, **1080p 창 스크롤 7.3배**.

### D — 라벨 왼쪽 / 값 오른쪽 축 정렬  (7.06)
`addStretch` 를 라벨과 값 **사이**로 옮겨 값들이 오른쪽 한 축에서 끝나게 한다.
카드 안 오른쪽 변이 4갈래(327/378/529/1448) → **1갈래(1171)** 로 모인다.

- 알려진 결함: **픽셀 회수량 0** — 행 안 총 공백이 1081 → 1081px 로 완전히 동일.
  오른쪽 띠가 줄어 보인 건 그 여백이 **읽는 길목(라벨↔값 사이)으로 옮겨 앉았기** 때문.
  1512px 에서 라벨↔값 간극 805~821px. 2560px 에서 카드 안 빈 띠 1342px(54%).

## 안과 무관하게 확인된 것

### 기존 버그: 800px 가로 넘침은 **래치**였다
5개 에이전트가 **독립적으로 같은 원인**에 도달했다. `_reflow_device_row` 가 가용 폭을
자기 호스트의 `width()` 에서 읽는데, 폴더 행이 한 번 2열이 되면 그 호스트의 **최소폭**이
908~972px 로 올라가고, 스크롤 영역이 호스트를 그 최소폭까지 키우고, 다시 그 부풀린 폭을
읽어 "아직 2열이 들어간다"고 판단한다 — 그래서 창을 줄여도 1열로 못 돌아간다.

- 재현 조건: **넓은 창에서 좁혀 올 때만**. 800px 로 처음부터 띄우면 넘치지 않는다.
- 실측: 1512→800 축소 시 가로 스크롤 **172~186px**, 640px 에선 418px.
- 다섯 안 모두 스크롤 **viewport** 폭(내용이 영향을 줄 수 없는 값)을 상한으로 씌워 끊었고,
  전 구간 스윕에서 재발 0건.

**어느 안을 고르든 이 수정은 함께 온다.** 안을 하나도 채택하지 않기로 해도
이 부분만 따로 떼어 반영할 가치가 있다.

### 측정 시 주의 — prefs 격리
빈 비율 지표는 `~/.aoi_verification_cache/ui_prefs.json` 의 `legacy_enabled` 에 좌우된다
(임계치 슬라이더가 보이면 수치가 달라진다). 실측 비교는 반드시 `AOI_DATA_HOME` 과 `HOME`
을 임시 폴더로 격리하고 **실제 QSS 를 적용한 뒤**(`theme.apply_to_app`) 재야 한다.
격리하지 않아 A·B 의 자기보고 수치가 실제와 어긋났다(B: 보고 22% → 실측 27.8%).

### 지표 자체의 한계
"내용 오른쪽 끝 → 창 오른쪽 끝" 이라는 지표는 **카드를 오른쪽 끝에 붙이면 정의상 작아진다**
(E 가 4%를 기록한 이유). 여백이 실제로 줄었는지 보려면 **행 안 총 공백**이나
**렌더 이미지의 최대 빈 직사각형**을 함께 봐야 한다 — D 와 E 는 이 지표로 재면
개선이 아니라 이동(또는 악화)이었다.
